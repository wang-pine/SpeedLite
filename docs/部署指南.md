# speedTest 部署指南

把 speedTest 部署到服务器并长期运行的完整步骤。**一个静态二进制**即可交付，无任何依赖。

---

## 一、构建

### 1.1 一键多平台构建（推荐）

```bash
# 读取 config/version.ini，构建全部平台（linux_x86/x64/arm/arm64/windows/darwin…）
./makeVersion.sh

# 产物在 dest/<平台名>/ 下，每个平台含：
#   speedtest-server / speedctl（静态二进制）、SHA256SUMS、发行包(.tar.gz/.zip)
ls dest/linux_x64/
```

需要改版本号时编辑 `config/version.ini` 的 `[version]` 段，或临时覆盖：

```bash
./makeVersion.sh 1.2.0
```

### 1.2 仅构建当前平台（开发调试）

```bash
cd src
go build -o speedtest-server ./cmd/speedtest-server
go build -o speedctl ./cmd/speedctl        # 可选：命令行客户端
```

### 1.3 静态构建（makeVersion 默认已静态，手动构建时注意）

`makeVersion.sh` 构建时自动 `CGO_ENABLED=0`（纯静态、无 glibc 依赖），
兼容 CentOS 7 / Ubuntu 18 等老系统——不会出现：

```
./speedtest-server: /lib64/libc.so.6: version 'GLIBC_2.34' not found
```

验证：`file speedtest-server` 应输出 `statically linked`。

### 1.4 其他平台（手动）

| 目标 | 命令 |
|---|---|
| Windows | `cd src && GOOS=windows go build -o speedtest-server.exe ./cmd/speedtest-server` |
| ARM 服务器（树莓派等） | `cd src && GOOS=linux GOARCH=arm64 CGO_ENABLED=0 go build -o speedtest-server ./cmd/speedtest-server` |
| 全部平台 | `./makeVersion.sh`（推荐） |

## 二、启动与验证

### 2.1 启动

```bash
./speedtest-server -http :8080 -tcp :5001 -udp :5201
```

| 参数 | 说明 |
|---|---|
| `-http` | Web 页面 + WebSocket（网页 TCP 测速）+ WebRTC 信令（网页 UDP 测速） |
| `-tcp` | 原生 TCP 测速端口（`speedctl` 用） |
| `-udp` | 原生 UDP 测速端口（`speedctl` 用） |

启动日志会打印监听端口。**三个端口都要在防火墙放行**（至少要放行 `-http`）。

### 2.2 验证

```bash
curl -sI http://127.0.0.1:8080/ | head -1    # 期望 HTTP/1.1 200 OK
# 局域网设备浏览器打开 http://服务器IP:8080
```

## 三、长期常驻

### 3.1 nohup（最简单）

```bash
nohup ./speedtest-server -http :8080 -tcp :5001 -udp :5201 > speedtest.log 2>&1 &
```

- 日志在 `speedtest.log`。
- 重启：`kill $(pgrep -f speedtest-server)` 后重新启动。

### 3.2 systemd（推荐正式部署，开机自启 + 崩溃自动拉起）

创建 `/etc/systemd/system/speedtest.service`：

```ini
[Unit]
Description=speedTest bandwidth tester
After=network.target

[Service]
Type=simple
WorkingDirectory=/opt/speedtest
ExecStart=/opt/speedtest/speedtest-server -http :8080 -tcp :5001 -udp :5201
Restart=always
RestartSec=3

[Install]
WantedBy=multi-user.target
```

启用：

```bash
sudo systemctl daemon-reload
sudo systemctl enable --now speedtest

# 常用管理命令
sudo systemctl status speedtest     # 状态
sudo systemctl restart speedtest    # 重启
sudo journalctl -u speedtest -f     # 看日志
```

> 注意 `WorkingDirectory`/`ExecStart` 换成你的实际路径。

### 3.3 Windows

- 双击运行，或 `start /b speedtest-server -http :8080 ...`。
- 首个运行会弹防火墙授权，放行 `8080/5001/5201`。
- 正式部署可用 NSSM 注册为服务：`nssm install speedtest` → 填程序路径与参数。

## 四、防火墙放行

| 端口 | 用途 | 是否需要对外放行 |
|---|---|---|
| `-http`（如 8080） | 网页 + 网页测速 | **必须** |
| `-tcp`（如 5001） | `speedctl tcp` | 用 CLI 就放行 |
| `-udp`（如 5201） | `speedctl udp` | 用 CLI 就放行 |

**Linux（firewalld）**：

```bash
sudo firewall-cmd --permanent --add-port=8080/tcp --add-port=5001/tcp --add-port=5201/udp
sudo firewall-cmd --reload
```

**Linux（ufw）**：

```bash
sudo ufw allow 8080/tcp && sudo ufw allow 5001/tcp && sudo ufw allow 5201/udp
```

**云服务器**：到控制台安全组放行对应端口（很多云默认只开 22/80/443）。

## 五、更新版本

```bash
# 1. 停旧进程
sudo systemctl stop speedtest          # systemd 方式
# 或 kill $(pgrep -f speedtest-server) # nohup 方式

# 2. 替换二进制（新文件直接覆盖）
cp speedtest-server /opt/speedtest/    # 或 scp 上传

# 3. 启动
sudo systemctl start speedtest

# 4. 客户端强制刷新页面（Ctrl+Shift+R）——旧 JS 缓存可能导致页面与新版不符
```

## 六、常见问题

**Q1：报 `GLIBC_2.34 not found`**
用了动态链接构建。改用 `./makeVersion.sh`（自动静态编译），或手动 `CGO_ENABLED=0 go build`（见 1.3）。

**Q2：8080 被占用（address already in use）**
换端口：`-http :8090`；或先杀掉占用进程。注意旧版进程可能仍占着端口：`ss -tlnp | grep 8080` 找到 PID 后 kill。

**Q3：网页能打开但测速全 0 / 报"无法连接测试服务器"**
- `-http` 端口被防火墙/安全组拦截（最常发生在云服务器）。
- 浏览器连的是别的服务器（检查顶部「服务器」显示）。
- 旧浏览器不支持 WebRTC（UDP 测速报错，TCP 应正常）。

**Q4：内网穿透 / 公网部署时 UDP 测速失败**
WebRTC 需要双向 UDP 可达。公网部署建议用 TCP 模式测速（UDP 另用 `speedctl` 从服务器侧验证）。

**Q5：多网卡 / 绑定了错误 IP**
`-http :8080` 监听所有网卡；如需指定，写具体 IP：`-http 192.168.1.10:8080`。

## 七、带宽测试建议

- **预期值参考**（千兆内网，TCP 4 流 10s）：下行/上行 ≈ 940–980 Mbit/s；UDP 网页 ≈ 200–900 Mbit/s（看包大小与浏览器）。
- **先网页快速验证，再 speedctl 精确测**：网页省事（手机也能测），speedctl 贴近线速。
- **测速结果 = 端到端管道能力**：受交换机协商速率、网卡、对端 CPU、浏览器协议栈共同影响；慢是链路真实情况时，对账会明确提示"结果不可信"。
