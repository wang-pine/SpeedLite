# speedTest 用户手册

使用 speedTest 测速的完整教程：网页端、命令行端、结果怎么读。

---

## 一、网页测速（Web 控制台）

### 1.1 打开页面

浏览器（PC / 安卓均可）访问：

```
http://服务器IP:8080
```

页面上方显示当前连接的服务器地址。若服务器不在本机，可在「服务器地址」输入框里填目标服务器（如 `192.168.1.10:8080`），留空则测当前页面所在服务器。

> ❗ 改过服务器后若页面没变化，请强制刷新（`Ctrl+Shift+R`），避免浏览器缓存旧版页面。

### 1.2 配置项

| 配置项 | 可选值 | 默认 | 说明 |
|---|---|---|---|
| 模式 | TCP / UDP / TCP+UDP | TCP | TCP 走 WebSocket；UDP 走 WebRTC DataChannel（真实 UDP 封装）；联测模式两条链路顺序跑 |
| 方向 | 下行 / 上行 / 双向 | 下行 | 以你的视角：下行=服务器→你；上行=你→服务器 |
| 并行流数 | 1 – 16 | 4 | 多流可榨干多核 CPU / 多队列网卡；单流适合低带宽链路 |
| 时长（秒） | 1 – 120 | 10 | 越长越稳；快速验证用 3–5 秒 |
| 包大小（字节） | 1KiB – 1MiB | 128KiB | 大包吞吐高；小包更考验处理能力（丢包更明显） |

### 1.3 开始 / 停止

- 点 **▶ 开始测速** 启动。窗口内实时显示：下行 ▼ / 上行 ▲ 当前速率、进度条、累计传输量、阶段文字（连接中/测速中/汇聚中…）。
- 点 **■ 停止** 可提前终止当前测试。
- 测速中再次点开始会先停止再重新测。

### 1.4 实时曲线

- canvas 绘制上下行两条速率曲线：**下行实线、上行虚线**，颜色区分不同链路/方向的缓存结果。
- 曲线按「模式+方向」缓存：**重新测同一链路会替换旧曲线；测新链路则追加**，可在同一张图对比多次结果。
- 点 **⟳ 刷新清空** 清掉当前缓存的曲线与结论表（localStorage 里的历史记录单独保留）。

### 1.5 读懂结果表

```
链路   方向      平均        峰值        总传输    交付损失 抖动   用时     时间
TCP    下行 ▼   948.7       1072.2      1.11 GiB  0%       —      10.1 s   09:39
       4 条并行流 · 下行 1.11 GiB · 服务器对账: 传输 1.11 GiB · 平均 909.0 Mbit/s · 峰值 1450.4 Mbit/s · 对账正常
```

**主行**——浏览器本地统计：

| 列 | 含义 |
|---|---|
| 链路 / 方向 | TCP 或 UDP / ▼下行 ▲上行 ⇅双向 |
| 平均 | 全程平均速率（Mbit/s）；双向显示 ▼下行/▲上行 两个值 |
| 峰值 | 1s 滑动窗口内的最高平均速率 |
| 总传输 | 本链路实际传输字节数 |
| 交付损失 | TCP 固定显示 0%；UDP 为 WebRTC 应用层已排空量与对端接收量的差额，不等于 IP 层包丢失率 |
| 抖动 | 网页无法精确测量，显示 `—`；精确值用 `speedctl udp` |
| 用时 / 时间 | 实际测速时长 / 完成时刻 |

**明细行**——服务端独立统计（双重对账）：

```
N 条并行流 · 下行 X · 服务器对账: 传输 Y · 平均 Z Mbit/s · 峰值 P Mbit/s · 状态
```

| 状态 | 偏差 | 含义 |
|---|---|---|
| ✅ TCP 对账正常（绿） | <1% | 有序结束边界内两端字节一致 |
| 🚨 TCP 对账异常（红） | ≥1% | result 前异常断链或协议边界不一致 |
| ✅ UDP 交付正常（绿） | <5% 且无残留 | WebRTC 应用层交付差额较小 |
| ⚠ UDP 交付损失较大（黄/红） | ≥5% 且无残留 | 已排空量与接收量存在应用层差额 |
| 🚨 队列截断（红） | 残留 >0 | 发送队列未在 3 秒内排空，不能据此判断网络丢包 |

> UDP 明细会同时给出“提交、排空、接收、残留”。只有排空量参与交付损失计算；残留单独标记为队列截断。若需要 IP 层包丢失率，请使用 `speedctl udp`。

### 1.6 历史记录

- 每次完成的测试自动进入页面底部的「历史记录」（最多 20 条，存 localStorage）。
- 「清空历史」按钮只清历史，不动当前曲线。

## 二、命令行测速（speedctl）

网页测的是"浏览器可达吞吐"，受协议栈开销影响。**极限/精确数值用 `speedctl`**（原生 socket，iperf 风格，贴近线速）。

### 2.1 语法

```bash
speedctl -s <服务器IP> [tcp|udp] [up|down] [flags]
```

位置参数：`mode`（tcp/udp，默认 tcp）、`direction`（up/down，默认 up）。
flags 可放在任意位置。

### 2.2 常用命令

```bash
# TCP 下行 / 上行（4 流 10 秒）
speedctl -s 192.168.1.10 tcp down -P 4 -t 10
speedctl -s 192.168.1.10 tcp up   -P 4 -t 10

# UDP 下行 / 上行（单流 60KB 包，丢包率低更准）
speedctl -s 192.168.1.10 udp down -P 1 -l 60000 -t 10
speedctl -s 192.168.1.10 udp up   -P 1 -l 60000 -t 10

# 服务器端口不是默认值时
speedctl -s 192.168.1.10 -tcp-port 5001 -udp-port 5201 tcp down -P 8 -t 5

# 快速验证（3 秒 2 流）
speedctl -s 192.168.1.10 tcp up -P 2 -t 3
```

### 2.3 参数表

| 参数 | 默认 | 说明 |
|---|---|---|
| `-s <host:port>` | `127.0.0.1:5001` | 服务器地址（HTTP 端口，非测速端口） |
| `-tcp-port <n>` | `5001` | 原生 TCP 测速端口 |
| `-udp-port <n>` | `5201` | 原生 UDP 测速端口 |
| `-P <n>` | 4 | 并行流数 |
| `-t <秒>` | 10 | 测速时长 |
| `-l <字节>` | 131072 | 包大小 |

### 2.4 CLI 输出示例（UDP 含丢包/抖动）

```
[udp] 下行 1 stream × 60000 B × 10.0s
  平均 941.2 Mbit/s   峰值 960.1 Mbit/s
  发送 1.10 GiB  接收 1.10 GiB  丢包 0.00%  抖动 0.12 ms
```

- **丢包率**：接收端按序号连续性统计（iperf 式 24B 包头）。
- **抖动**：RFC3550 平滑抖动。
- UDP 小包高 pps 时丢包率升高属正常（接收处理上限），大包单流通常 <0.1%。

## 三、常见问题（FAQ）

**Q1：测速结果全是 0 或连不上？**
检查：服务器是否运行、防火墙是否放行 `-http` 端口、浏览器是否连对地址。服务端启动日志里有监听端口信息。

**Q2：网页数字和 speedctl 差很多？**
正常。网页受浏览器协议栈（WS/WebRTC）开销影响，一般比原生 socket 低 5–15%，UDP 差更多。以 `speedctl` 为准，网页用于快速/移动端验证。

**Q3：UDP 网页交付损失很高？**
WebRTC DataChannel 是不可靠通道（`maxRetransmits:0`）。网页展示的是已排空应用负载与对端接收负载的差额；若同时出现“队列截断”，说明仍有数据留在发送队列，不能把差额解释成网络丢包。精确对比用 `speedctl udp`。

**Q4：峰值比平均高很多（比如平均 900 峰值 1600）？**
峰值是 1s 窗口内最高平均速率，测速启动瞬间协议栈可能先冲高再回落，属正常形态；上行已做 `bufferedAmount` 缓冲校正，避免"内存拷贝速度"假峰值。

**Q5：上行统计怎么算的？**
TCP 上行停止产生数据后，在同一 WebSocket 中追加有序 `stop`；服务端读到 stop 后才返回 result，因此此前数据已全部进入服务端统计。UDP 上行则先等待 `bufferedAmount` 排空，残留单独报告。TCP 双端偏差 <1% 才视为正常。

**Q6：换服务器版本后页面没反应？**
浏览器缓存了旧 JS。强制刷新：PC `Ctrl+Shift+R`，安卓长按刷新选"硬刷新"。

**Q7：speedctl 连不上？**
默认 `-s` 连的是 HTTP 端口（如 `8080`），不是原生测速端口。确认 `-s` 地址 + `-tcp-port`/`-udp-port` 与服务器启动参数一致。

## 附录 A：前端对账分级逻辑自测

需要 Node.js，无需安装 jsdom 或其他 npm 依赖：

```bash
cd src
node --test cmd/speedtest-server/web/app.test.mjs
```

核心断言（用真实用户数据形态）：

| 场景 | 输入 | 期望 |
|---|---|---|
| UDP down 提交 10MiB / 残留 4MiB / 接收 5MiB | `aggregate(...,'down')` | 排空 6MiB、交付损失≈16.7%、显示队列截断 |
| TCP down 正常对账 | 两端≈相等 | devPct<1%，明细含 `对账正常` |
| TCP down 偏差 1.2% | 两端边界不一致 | 明细含 `对账异常` |
